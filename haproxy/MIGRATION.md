# Миграция sites.conf v1 → v2

v2 обратно совместим: старые записи парсятся как раньше (проверено golden-тестом
— выхлоп v1 байт-в-байт). Миграция лишь добавляет блок `GLOBAL_OPTS`
со значениями = текущее поведение, т.е. **после миграции конфиги генерируются
те же самые**.

## За 3 команды

```bash
cd haproxy
./scripts/migrate.sh --dry-run   # 1. посмотреть, что получится (ничего не пишет)
./haproxy.sh → пункт 12          # 2. применить (спросит подтверждение, сделает бэкап)
./haproxy.sh → пункт 8           # 3. перегенерировать (покажет diff, спросит подтверждение)
```

## Что меняется в файле

До (v1):

```bash
ACME_EMAIL="mail@example.com"
WEB_SITES=( "site.com:8080" )
REALITY_SITES=( "vpn.com:10443" )
```

После (v2) — то же плюс блок:

```bash
GLOBAL_OPTS=(
  "timeout_connect=5s"
  "timeout_client=50s"
  "timeout_server=50s"
  "bind_stream=*:443"
  "bind_web=*:8443"
  "blackhole=deny"
)
```

Сгенерированные `haproxy.cfg` после миграции идентичны предыдущим —
проверь пунктом 8 (должно сказать «без изменений») или `bash tests/run.sh`.

## Откат

Миграция кладёт бэкап в `.backup/<дата>-pre-migrate/`. Откат: п.10 меню
(«Бэкапы и откат») → выбрать `pre-migrate` → перезапустить сервисы (п.5).

## Дальше (опционально)

После миграции можно точечно включать фичи v2 правкой `GLOBAL_OPTS`
(примеры — в `sites.conf.v2.example`): таймауты `1h`, `bind_web=127.0.0.1`,
`tarpit`, PROXY-пару, path-правила (`"домен:порт:path=/prefix"`),
per-entry reality-бэкенды (`"домены:порт:proxy=v2"`).
